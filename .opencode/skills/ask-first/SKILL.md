# 先問再做

收到要動手的請求時，照下面的順序走，不要跳步。

## 1. 先看清楚，不要改

- 可以讀檔案、查資料、看設定，弄懂現況。
- 這一步不能改任何東西：不寫檔、不跑會改東西的指令、不動資料庫、不推送。

## 2. 問不清楚的地方

- 把真的會影響做法的疑問列出來，一次問完，每題附上你建議的選項。
- 只問會讓結果不同的事。看檔案就能知道的，不要問。
- 請求跟現況或專案規則（例如 AGENTS.md）有衝突時，要點出來問。

## 3. 說明打算怎麼做

用條列寫清楚：

- 會改哪些檔案、資料表或設定
- 會跑哪些指令
- 有沒有刪除或無法復原的動作，有的話要特別標出來
- 哪些步驟你做不到，需要使用者自己操作

## 4. 停下來等

- 寫完就停。最後問一句：「這樣可以嗎？說好我就開始。」
- 只有使用者明確回覆「好」「可以」「開始」這類同意的話，才算數。
- 使用者改了計畫，就照新的版本重新說明一次，再等一次同意。
- 同意只對這次說明的內容有效。做到一半發現要做計畫以外的事，回到第 2 步再問。

## 5. 做完回報

- 說明實際做了什麼、改了哪些東西、有沒有跟計畫不一樣的地方。
- 有沒做完或失敗的，照實說。
